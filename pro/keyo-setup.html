Keyo licensing patch

This patch is for the supplied Taskitator-main-9.zip. It fixes subscription activation and ongoing license validation. It preserves hosted credit charging, balances, usernames, tasks, sync, verification and batch behavior. Batch-completion hardening and Phase 3 are separate work.

1. Replace the files

Extract this patch into your existing Taskitator repository root, replacing matching paths. Do not upload it as a new nested application folder. The ZIP includes only changed or new files; all new files are under pro/. Keep your remaining project files.

The deployed Worker imports pro/pro-backend.js through cloudflare/worker.js. Root-level duplicate backend files are not the deployment entry point. Extracting only worker.js will not install this patch.

2. Deploy the Worker and website

  1. From the repository root run npm test.
  2. Redeploy the existing Worker with npm run deploy:worker. This uses cloudflare/wrangler.toml and updates the existing taskitator-sync Worker. If using the existing GitHub workflow, run Deploy Taskitator security Worker manually after committing the patch. Follow its result to confirm deployment succeeded.
  3. Publish the updated website files through your usual website deployment. Reopen Taskitator and refresh Settings. The UI change shows lifetime licenses correctly and explains when an old grant needs reactivation.

No new D1 schema, KV namespace, R2 bucket or Durable Object migration is required. Preserve existing Cloudflare bindings and secrets. The included Wrangler file retains the uploaded project's bindings and migration history.

4. License behavior

  • Activate with a real 16-character Keyo subscription key from the Taskitator project; spaces and hyphens are accepted. Supported tiers are PRO and MAX (case insensitive). Other tiers do not grant Taskitator Pro.
  • Taskitator sends the signed-in Clerk user ID as Keyo's accountId. Keyo controls account limits and assignment. If you manually assign a key, use that Clerk user ID, not the Taskitator username or email. Existing bindings to a different identifier require reassignment in Keyo.
  • Raw activation keys are sent to Keyo over HTTPS and are not stored or logged by this patch. Taskitator retains the signed entitlement and a SHA-256 fingerprint.
  • Previously accepted unsigned grants no longer authorize Pro. Those users must enter a real Keyo key again. An old signed grant is accepted only after signature validation and an online verification against Keyo.
  • Accepted licenses are checked locally on status, BYOK toggles and hosted audit requests, with online refresh after one hour. Revocation, suspension, deletion, expiry and changed bindings are rejected on refresh. A cached license can therefore remain usable before its next refresh. During a temporary Keyo outage, previously verified access can last only until the signed deadline, at most 24 hours from issuance; it cannot be extended locally. An explicit denial or invalid refreshed token ends access.
  • Lifetime licenses retain a null license expiry, but still require the short signed verification window and periodic refresh. No artificial one-year expiration is added.
  • Reactivation and refresh preserve usage, spending reservations and the BYOK preference. Limits remain 45 daily and 1,000 monthly credits; this patch does not change charging.
