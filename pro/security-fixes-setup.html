Taskitator security and breaks patch

23 October 2026. Apply this patch to the supplied Taskitator-main-9.zip. It also includes the earlier Keyo licensing patch, so you can apply this combined package directly. Only changed/new files are included, preserving repository paths. Every new file is inside pro/.

Deploy both parts

  1. Keep a copy of your current repository. Extract the patch into its root and replace all matching files. Keep your other application files.
  2. Run npm test from the repository root.
  3. Deploy the existing Worker using npm run deploy:worker, or run the existing GitHub workflow Deploy Taskitator security Worker. Its entry point is cloudflare/worker.js, importing the new modules under pro/. Uploading only a standalone worker.js does not install this update.
  4. Publish the updated website, including pro/break-core.js, the updated application pages, scripts, sw.js and auth-bootstrap.js. Deploy the Worker before opening the new website.
  5. Close old Taskitator tabs and reopen the site. The new cache version is taskitator-security-breaks-v5. Refresh all devices before submitting proof or changing break plans.

No new database, schema migration, storage binding, Clerk session claim, Google OAuth setting or Keyo secret is required for this patch. Keep the existing bindings and secrets. Keyo's public project settings remain included in cloudflare/wrangler.toml. Your deployed Keyo subscription API works with this patch; deploying consumables is optional.

Protected tasks and approvals

  • AI reviews use the server's saved task criteria and reference files. Tasks sync before review, and both hosted and personal-key proof reviews create a server approval.
  • Confirmation completes tasks on the server. Approvals bind the original account/session, reviewed evidence and task revisions, and are valid for 24 hours. An identical confirmation retry returns the existing result; a different reuse is rejected. The browser downloads the authoritative task state and preserves drafts if local edits occur during confirmation.
  • Parent completion respects unfinished protected children and task shields. Recurring branches advance through the existing recurrence rules. Stored audit history is updated in the same completion transaction.
  • Old approvals and old pending price previews must be recreated. Five failed AI responses no longer count as approval.
  • References created by older versions may exist only on one device. Use that device for the first review: the updated app uploads the local reference before requesting the audit. Confirm the original file is available. A server cannot reconstruct an old reference file that was never uploaded. New references are included when tasks sync.
  • If an old tab has an unsynced protected completion, keep a backup of its local edits, refresh, and use the conflict dialog to restore the cloud copy before reviewing again. An intentional Emergency Bypass can also authorize the change. The patch does not silently approve old local completions.

Emergency Bypass

The existing four-use, 15-minute bypass is now authorized by the server and shared across devices. Starting a bypass requires a connection. Its weekly reset is pinned when the server cycle is created; changing weekend settings does not refill tokens midway through that cycle. Browser-only bypass windows from older versions are not trusted; activate a new window in the updated app. The server starts its initial cycle with four uses because no reliable server record of the old local-only usage exists.

Deletion and temporary records

Account deletion now removes Taskitator license entitlements, old key bindings, preview state and emergency state. It also removes any matching row in the optional D1 entitlement mirror. New activations use the Durable Object entitlement record rather than creating duplicate D1 license copies. Requests that finish after deletion cannot recreate the removed license, approval, usage or spending records. External Keyo subscription keys are not automatically deleted.

Exhausted accounts are rejected before external token counting. Each account can run one preview count at a time, request at most 12 previews per minute and hold at most 12 unused previews. Unused previews expire after five minutes and are removed by paginated background cleanup. Finished operation records are retained for the safe retry window, up to 24 hours, then removed; expired operation IDs cannot start inference again.

Uncertain, interrupted paid requests retain their spending reservation and operation record until reconciled. The cleanup job deliberately retains pending paid operations so a retry cannot cause a second charge. If a Worker interruption leaves one pending, check provider usage before manually reconciling it; do not simply delete its operation record or reservation.

Break scheduling

  • The 10-minute planning deadline stays fixed when the modal closes, the page reloads or another device opens the plan. Starting and sealing a plan trigger a sync push; edits are also marked for the normal sync batch. Offline changes wait for connectivity. A suspended browser cannot send a request until it resumes, but the saved absolute deadline continues to apply.
  • Enter 1–3 complete, non-overlapping breaks totalling at most 3 hours. Empty or invalid rows cannot seal an empty schedule.
  • At expiry, the last valid schedule is sealed. If none exists, the cycle allows one valid repair: enter complete times and confirm. This also recovers old empty lockouts. Repair does not restart the 10-minute countdown.
  • Breaks use the planning device's timezone, carried with absolute start/end timestamps to the Worker and other devices. Legacy local schedules are converted when read by the updated app; verify an old schedule if you changed timezone since planning it. The current cycle keeps its pinned timezone and day-start setting.
  • Both browser and Worker accept clock seconds and treat a break as active from its start until, but excluding, its end. Overnight breaks continue across midnight and count toward their originating cycle's 3-hour allowance. The active countdown also continues across that boundary.
  • The status pill remains visible in all task-list views and refreshes once per second. Statistics and Ari use the current cycle's break list rather than treating the date dictionary as an array.
  • Old break records beyond 90 days are pruned during normalization and sync. Phone status evaluates only nearby dates, rather than scanning all historical entries. If you need older break history, keep an existing backup before using the updated app.
