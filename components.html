          Import or connection not working?
          • The browser shows file text: use its Download / Save link option and keep the .macro extension. Import the saved file from MacroDroid. If your host returns a missing-file page, use the Download macro button above to save Taskitator-Cloud-Bridge.macro directly.

          • 401 / Unauthorized: check the phone token and Bearer prefix. Replacing or revoking a phone token invalidates the old one.
          • UnknownHostException / unable to resolve host: check the URL, internet connection and DNS. This is a connection error, not a Taskitator unlock response.

          Hosted AI Credits & Dynamic Charges

          Pro accounts include 45 daily credits and 1,000 monthly credits (resetting in Asia/Riyadh time). Instead of flat per-file fees, charges are calculated dynamically from the actual work required: PDF document page count, photo resolution, and review output. Before any paid review starts, a readable preview shows your estimated charge and maximum temporary hold. Once the review completes, unused held credits return immediately. Completed reviews are charged even when proof is rejected.

          Reference Examples (×2) & Batch Discounts (25% Off)

          When a task includes a saved reference example (exemplar), the AI compares your proof against that exemplar side by side, which applies a ×2 multiplier to that task’s credit charge. When you review 2 or more tasks together in Batch Proof Review (up to 20 tasks and 5 shared files), each task receives a 25% batch discount because the shared evidence is inspected in a single pass.

          Personal API-Key Mode (BYOK) vs. Hosted Credits

          Both Free and Pro users can save personal Gemini or Claude API keys in the encrypted server vault. Pro users can switch Personal BYOK Mode on or off in Settings at any time. Using your own API key routes requests through your personal provider account while keeping your hosted Pro credit balances and limits intact without resetting them.

          Consecutive Subtask Creation

          In both the Create Task and Task Details dialogs, enabling Consecutive {num==X} (PRO) automatically advances the number token each time you press Enter in the quick-subtask field. Free accounts and expired Pro accounts retain full manual subtask creation and can type any task titles manually, and all previously created subtasks keep their numbering if a Pro license expires.

          6. Optional AI and API keys

          When you use an AI feature, Taskitator sends the relevant request through its Cloudflare Worker to the active provider: Google’s Gemini service or Anthropic’s Claude service. The Worker processes the request and response in transit. Depending on the feature, a request can contain task information, prompts, proof criteria, conversation context, and images or documents you provide for proof or reference review.

          Saved Gemini and Claude API keys are stored separately and encrypted using AES-256-GCM in server-side storage. The encryption keyring is held as a separate Cloudflare Worker secret. Normal AI requests use the active provider’s saved key on the server rather than returning it to your browser. Browsing a provider in Settings does not activate it: use the provider activation button to choose which service receives AI content. Copilot context is reset when providers change, and failures do not automatically route content to a different provider. Showing, copying, replacing or deleting a saved key requires a short-lived, one-use password or linked-Google confirmation. Google may accept an existing Google session; Taskitator checks that the verified identity matches the linked account. A revealed key is temporarily held in browser memory, and a copied key may remain in your operating system clipboard.

          Before legacy plaintext key fields are removed from attributed browser/cloud copies, the update preserves them encrypted. Browser-only and historical recovered keys require a verified selection before they become active. Unreadable or unattributed records, old exported files and devices that have not run the update may retain plaintext copies and need separate review. Updated cloud snapshots and ordinary exports omit API keys.

          This is encryption at rest, not end-to-end encryption. The Worker decrypts a key when needed; an operator or attacker controlling the Worker and its secrets could access it. Connection tests request model metadata without generated tokens, and do not establish generation quota or billing availability.

          Google’s and Anthropic’s handling of AI requests depends on the applicable provider terms and the account/API configuration you use. Do not assume AI requests are confidential or excluded from provider retention or improvement practices. Avoid submitting sensitive material you do not want processed by that provider.

          7. Cookies, browser storage, and security

          Clerk uses its own authentication/session mechanisms, including cookies. Taskitator uses browser local storage and session storage for settings, drafts, synchronization state, and recovery copies; IndexedDB stores local reference files. A service worker caches static application files.

          These three public information pages do not load authentication scripts, analytics scripts, or external fonts, and do not create their own tracking cookies. Hosting providers still process ordinary requests to deliver them.

          Authenticated cloud requests require a valid Clerk session and account-ownership checks. Phone tokens are limited to unlock-status access; the server stores their digest. Local drafts and reference files are not encrypted, and cloud data is not protected by end-to-end encryption. No system can guarantee complete security. Use a separate browser/device profile on shared devices and protect your account and keys.

          8. Retention

          Current synchronized workspace data and account records are retained while needed to provide the service and until they are removed through account deletion or an available support process. This version does not impose a fixed automatic account-retention period for active accounts.

          Once cloud deletion is accepted, account access is blocked and a retryable cleanup job removes the current workspace, account link, and identifiable legacy records before removing the Clerk login. Necessary cleanup identifiers remain while that job is pending; failures may require operator assistance.

          To reduce phone lockout, active phone-token digests are retained as status-only recovery records for seven days from deletion acceptance. They return unlocked status and grant no task access. Minimal hashed deletion receipts and anti-resurrection markers are retained temporarily: receipt/status records expire seven days after completion, and legacy-migration prevention records expire seven days after acceptance. Short-lived verification/replay records are also removed after expiry. Old username/email migration approvals in Cloudflare deployment settings are separate from application data; Mazendev must remove an approval entry manually if it is still present. The deletion status page flags this condition.

          Local drafts, recovery archives, cached files, and reference files can remain on other devices after deletion. Legacy records that are unreadable and cannot be linked to an owner are not guessed at or deleted automatically. Providers may retain operational/security records or backup copies under their own policies. A downloaded backup remains wherever you save it until you delete it.

          9. Access, correction, and deletion requests

Pressing the final deletion button accepts an irreversible cleanup request.

          Password confirmation is handled by Clerk. Google confirmation uses an additional authorization flow and checks the Google identity against the one linked to your account; Google may reuse an existing session rather than require a new password. The confirmation is bound to your Taskitator session and a short-lived, one-use action.

          After acceptance, cloud access is blocked immediately. The cleanup job removes synchronized workspace data, encrypted API-key and recovered-key records, account/credential links, and identifiable retained legacy copies, then deletes the Clerk login. Identified local archives and reference files in the initiating browser are cleared where possible. The status page reports completion or retrying cleanup.
